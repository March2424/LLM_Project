当前协议为选择器SFT，不训练翻译器。执行顺序：序列冷启动 → 冻结当前历史与候选 → Teacher自然语言分析/选择 → 独立固定基线翻译 → 未审记忆写回 → 下一条。当前译文不进入当前选择输入或SFT标签；前序译例可以进入后续候选。命令见 [TEACHER_TRAJECTORIES.md](TEACHER_TRAJECTORIES.md)。

## 后续链路复核：DPO冷启动和上下文（2026-11-02）

用户确认固定基线只写回一次，并允许术语/角色合组、STM/LTM合组。无需拆改现有retrieve_game：四组轮流装填，观察仍保留五类memory_kind；不保证每个细类至少一条，最终选择也无类别配额。池16、软选择0–8、组合软预算1024，硬项另计且不能被选择器删除。当前源文、语言方向、原生上下文/已知条件、候选正文/关系/token成本与预算均已进入观察；原始来源/版本和ReadView在ContextPack审计中保留。

DPO新序列先约10条固定基线冷启动，再冻结状态，pi_SFT尝试M=2–4条动作。每个合法不同上下文交外部LLM生成译文，评分提取的是完整动作偏好，而非译文偏好；r不传给Translator。各分支期间共享记忆不变，结束后固定基线只推进一次，不按参考分选历史。回放现有Teacher快照可复用已完成的冷启动与历史，不重复写回。

代码核对结论：Teacher生成、独立记忆翻译、冷启动、SFT导出和训练配置已有；开源学生动作采样、逐动作外部翻译编排、独立评分及偏好配对入口尚未实现。它们是下一阶段工作，不能把可复用的翻译适配器当作已经完成DPO链路。细节与步骤见 [LOONG_RL_PLAN.md §5.1](LOONG_RL_PLAN.md#51-两阶段数据生成teacher-sft-示范--pi_sft-自采样)。
