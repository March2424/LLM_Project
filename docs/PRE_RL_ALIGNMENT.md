## 2. 先对齐五类记忆的职责

| 记忆 | 写什么、从哪里来 | 何时读取/更新 |
| --- | --- | --- |
| 术语 | 批准术语或本运行经过核验的源译名称；源图中的英文实体名本身不等于已批准译名 | 当前文本确实适用时读取；歧义/冲突显式返回 |
| 角色 | 多条源侧风格证据形成的简短笔记，保留条件；身份未知可为空 | 按确认的人物身份读取；不能把一次异常语气当作永久风格 |
| 摘要 | 实体/主题相关资料的源侧概览，以及本运行已验证译文的目标侧表达 | 按新增信息节流更新，从有效底层证据重建；不把文件行序写成剧情顺序 |
| STM | 当前运行近期提交且相关的已验证译例 | 按相关性与提交时间读取，不等于前几行或对话前文 |
| LTM | 当前运行更广范围的相关已验证译例 | 与 STM 去重后召回；同一译例只保存一份 |

需要明确：冷启动哪些为空、哪些可以仅凭源文生成、什么检查允许写回、失败如何记录。尤其现有主题双语摘要需要相关译例，无译例时为空；不应把空类别视为流程失败。参考译文不进入这五类在线记忆。

## 3. 当前优先修正的接口问题

1. **存储/名称（已实现）**：复用 SQLite 与内存索引；仅大小写/空白处理，不做别名映射或实体合并。同名命中汇总原文，按 ID/版本去重。
2. **记忆组织键（已调整）**：仅唯一、直接且适用的链接派生 speaker/topic，不再按 ID 任取主题；多对象可召回，身份仍分别保留。角色/主题记忆可能分散，先接受此代价，不建立身份映射。
3. **条件（已调整）**：只对源侧软参考放宽 requirements 整值相等，展示原始 context；分支/阶段、硬规则和正式记忆检查仍保留。摘要写回仍过滤条件不符的来源。
4. **规则边界（保留）**：硬术语不可裁剪，格式/占位符由流程检查；源图关系是带来源参考。
5. **输入/动作（已实现）**：池 16 项、当前动作 0–8 项、软预算 1024；冻结 tokenizer，非法/超预算动作报错，实际正文与 manifest 一致。1024 不含当前源文、硬项和模板，也不是 4B 的完整观察窗口。
6. **性能/诊断（已实现）**：名称、邻接和词法索引按快照缓存，源版本/失效变化后重建；三库完成源侧抽样，不据此宣称翻译有效。

## 5. 最小验收场景

- 跨文件提到技能或物品时能找到对应定义；同名重复节点能扩展召回，错误别名不会直接写成身份事实。
- 无说话人、无实体或无 context 的短句可以正常返回少量/空证据，不编造背景。
- 多实体文本可以召回多个对象，不只依赖一个任意 topic_id。
- 分支/阶段确实不兼容的事实不会混用；本可作为含义参考的资料不会仅因无关条件文本不同而全部被过滤。
- 刚通过验证的译文能进入本运行的相关 STM/LTM，并保持去重；失败译文不进入正式 TM，另一运行读不到它。
- 角色笔记只作用于合适人物；摘要能追溯底层来源，未知或冲突信息不被总结成确定事实。
- 更新源文、图证据或记忆版本后，受影响记录失效；不会继续接受旧候选对应的验证结果。
- 输入清单与实际喂给模型的正文/ID/版本一致；记录截断、预算冲突、空召回、失败与成本。

先看必要证据召回、错误证据、重复率、token、延迟和日志中的具体例子，不为所有行为堆测试；重点补充现有模拟测试没有覆盖的真实源库情况。

## 6. 进入 SFT＋DPO 前的最低条件

- 固定选择器下，真实闭环能运行；关键隔离/失效/硬约束场景通过，真实样本中的主要召回失败有明确解释。
- 固定候选池中存在有用证据，翻译器能够利用它；若候选池本身缺资料，不期待选择器补救。
- 建立训练/测试划分（当前不设dev），按资源对象、任务/场景或模板族分组并检查重复；声明各阶段可读取的源资料范围。测试参考不参与训练、在线记忆或奖励。
- 评分子集参考译文经过必要审核；Naev fuzzy 等不能直接当确认参考。短名称、UI 的指标适用性需单列，不只用单一分数掩盖术语/格式错误。
- 选择器只输出合法软候选 ID；硬项不可删除；超预算、非法 ID、失败与回退的处理固定且可重放。
- 同一状态的偏好候选使用完全相同的记忆快照、候选池、翻译环境和预算。每个对照运行隔离目标记忆。
- 先做少量离线选择/评分试采样，确认能产生有意义、非噪声主导的质量差异，再扩展 SFT/DPO 数据与 GPU 训练。
